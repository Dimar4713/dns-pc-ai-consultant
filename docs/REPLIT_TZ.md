# Техническое задание: AI-консультант по подбору компьютера

## 1. Назначение

Создать в Replit простое веб-приложение с чат-интерфейсом. Приложение консультирует пользователя по подбору комплектующих компьютера на основе локальной базы знаний, подготовленной по разделам DNS.ru, и обращается к LLM через OpenAI-совместимый API RouterAI.ru.

## 2. Границы учебного проекта

- Приложение не парсит DNS.ru в реальном времени.
- Приложение не оформляет заказ и не проверяет фактическое наличие.
- База содержит учебную выборку товаров и правила совместимости.
- Цены и остатки пользователь проверяет на DNS.ru для своего города.
- Основной интерфейс — чат; настройки открываются отдельной кнопкой и не превращают приложение в каталог.

## 3. Технологический стек

- Replit, Node.js 20+.
- Backend: Express.
- Frontend: HTML, CSS и JavaScript без фреймворка.
- LLM API: RouterAI, OpenAI-compatible endpoint.
- Endpoint: `https://routerai.ru/api/v1/chat/completions`.
- Хранение настроек на учебном стенде: `localStorage` браузера.
- База знаний: файлы `data/knowledge-base-*.md`.
- RAG-lite: объединение MD-файлов, разбиение по заголовкам и лексическое ранжирование релевантных разделов без внешней векторной БД.

## 4. Пользовательский сценарий

1. При открытии показывается приветствие.
2. Консультант предлагает ответить на 2–4 группы вопросов:
   - бюджет и состав бюджета;
   - задачи, игры, разрешение/FPS либо рабочие программы;
   - уже имеющиеся компоненты;
   - шум, размер, внешний вид, Wi‑Fi и будущий апгрейд.
3. После получения достаточных данных консультант выдаёт персональную презентацию:
   - основная рекомендуемая сборка;
   - объяснение выбора;
   - проверка совместимости;
   - альтернатива дешевле или мощнее;
   - что проверить в карточках DNS.
4. Затем пользователь продолжает задавать вопросы, а консультант отвечает по базе знаний и истории текущего чата.

## 5. Функциональные требования

### 5.1. Чат

- Вывод сообщений пользователя и ассистента.
- Многострочный ввод.
- Enter отправляет, Shift+Enter создаёт новую строку.
- На время ответа блокировать повторную отправку.
- Показать нейтральный индикатор «Подбираю совместимые компоненты…».
- Автопрокрутка к последнему сообщению.
- Мобильная адаптация.

### 5.2. Приветствие

Текст должен:

- представлять консультанта;
- сообщать, что база учебная;
- сразу задавать три компактных вопроса, покрывающих требования задания.

### 5.3. Настройки RouterAI

- Кнопка с шестерёнкой в шапке.
- Поле API-ключа.
- Выпадающий список моделей.
- Возможность указать произвольный ID модели.
- Сохранять ключ и выбранную модель после перезагрузки через `localStorage`.
- Не выводить ключ в чат, лог сервера или текст ошибки.

Предустановленные модели:

- `deepseek/deepseek-v4-pro` — модель по умолчанию;
- `qwen/qwen3.5-35b-a3b` — экономичная;
- `openai/gpt-5.6-luna` — сбалансированная;
- `anthropic/claude-sonnet-5` — премиальная.

### 5.4. Backend API приложения

`POST /api/chat`

Вход:

```json
{
  "apiKey": "routerai-key",
  "model": "deepseek/deepseek-v4-pro",
  "messages": [
    { "role": "user", "content": "Нужен игровой ПК..." }
  ]
}
```

Выход при успехе:

```json
{
  "answer": "Текст ответа модели",
  "model": "deepseek/deepseek-v4-pro"
}
```

Ошибки:

- 400 — нет ключа, модели или сообщения;
- статус RouterAI — ошибка провайдера;
- 502 — сеть или некорректный ответ модели.

### 5.5. Формирование запроса к LLM

- Добавить системный промпт из `prompts/system-prompt.md`.
- Выбрать 7 наиболее релевантных разделов базы.
- Обязательно включать правила совместимости, алгоритм подбора и ограничения честности.
- Передавать не более 24 последних сообщений.
- Температура около 0,25 для устойчивых рекомендаций.
- Ограничение ответа около 1700 токенов.

## 6. Требования к базе знаний

База должна содержать:

- категории комплектующих;
- примеры реальных товаров;
- сокеты AM4, AM5, LGA1700 и LGA1851;
- DDR4/DDR5;
- ATX, microATX, Mini‑ITX и E‑ATX;
- PCIe, M.2 SATA/NVMe;
- требования к БП и разъёмам GPU;
- проверку высоты кулера и длины видеокарты;
- предупреждения по BIOS;
- типовые профили сборок;
- цены-ориентиры, ссылки DNS, дату среза и ограничения актуальности.

## 7. Нефункциональные требования

- Интерфейс работает на телефоне и компьютере.
- Нет базы пользователей и регистрации.
- Нет внешней БД.
- Нет логирования API-ключа.
- Код понятен учащемуся и не требует сложной инфраструктуры.
- Секрет не должен попадать в репозиторий.
- В production предпочтительно хранить ключ на сервере в Replit Secrets; `localStorage` оставлено только для выполнения условия учебной работы.

## 8. Критерии приёмки

1. После запуска виден чат и приветствие с 2–4 вопросами.
2. Без ключа приложение открывает настройки или сообщает, что ключ нужно задать.
3. После сохранения и перезагрузки ключ и модель остаются выбранными.
4. Запрос уходит на RouterAI с выбранным `model`.
5. Консультант не выдаёт сборку до получения достаточных требований.
6. В итоговой рекомендации есть проверка сокета, RAM, корпуса, БП, охлаждения и накопителя.
7. Консультант предупреждает о динамических ценах и наличии.
8. Процессор без iGPU не рекомендуется для системы без видеокарты.
9. DDR4 не смешивается с DDR5.
10. ATX-плата не предлагается для корпуса только microATX.
11. Три тестовых сценария проходят без критических ошибок.
12. `npm test` подтверждает работу HTTP-контура на mock RouterAI без расходования средств.

## 10. Риски и способы парирования

- **Устаревание каталога:** указывать дату среза; не обещать цену и наличие.
- **Галлюцинации LLM:** низкая температура, строгий системный промпт, выдача только релевантных фрагментов базы.
- **Несовместимость:** обязательный чек-лист перед каждой сборкой.
- **Компрометация ключа:** для учебного режима localStorage; для публичной версии — Replit Secrets и серверный ключ.
- **Рост базы:** перейти на embeddings и векторный поиск, когда объём станет существенно больше.
